# Phase 4 — the debate on further multi-hop benchmarks

Phase 4 asks one question: **does the pattern of Phase 3 hold beyond HotpotQA?**
The Phase 3 debate runs unchanged on two more benchmarks, **MuSiQue** (harder,
2–4 hops, up to about 20 paragraphs per question) and **2WikiMultiHopQA** (other question
types, 10 paragraphs). MultiHop-RAG is optional and not implemented yet.

Everything runs as in Phase 3: one node with 8 H200, same vLLM environment
(`vllm-p3`), same models, same conditions, judge as a separate pass.

## What is reused, what is new

| Part | Status |
|---|---|
| `xmad_debate/` (session, debate loop, judge), `prompts/`, `templates/` | **copied unchanged** from `3_iteration` (check: `diff -r ../3_iteration/xmad_debate xmad_debate`) |
| `servers.py`, `serve_mcp.py`, `smoke_test.py`, `models.yaml` | copied (only comments changed). `models.yaml` keeps the Phase 3 exclusions as prior knowledge |
| `smoke/` | **empty**: Phase 4 runs its own smoke tests (`run_phase4.sbatch` does this first for every model of the selected runs + the judge) |
| `config/base.yaml` | Phase 3 conditions unchanged; the single `dataset` entry is replaced by a `benchmarks` block |
| `xmad_bench/` | **new**: one adapter per benchmark -> `Example(question, answers, paragraphs, gold_titles, meta)`; scoring as max over all gold answers; evidence recall |
| `run_debate.py` | Phase 3 harness, generated by explicit replacements: reads questions through `xmad_bench`; new CSV columns `benchmark`, `q_meta`, `gold_answers`, prompt/completion tokens per agent, evidence recall (round 1 per agent and both together, all rounds) |
| `phase4.py` | Phase 3 orchestrator; runs carry a `benchmark`; `--benchmark` filter; judge re-scores against all gold answers; `repair` dropped |
| `run_phase4.sbatch` | Phase 3 batch job with `phase4.py` |
| `download_benchmarks.py` | **new**: official releases of the authors -> `data/<benchmark>/` + `SOURCE.json` (URL, date, sha256, counts) |
| `retriever_check.py` | **new**: recall@k of the bge retriever per benchmark (as the Phase 1 retriever table) |
| `tests/test_phase4_offline.py` | **new**: adapters, scoring, evidence recall, harness end to end with fake servers |
| `runs.yaml` | generated from the Phase 3 plan: every Phase 3 pair once per benchmark (66 x 2 = 132 runs, no replicates, no excluded models) + regression run `P4-HPQ-001` |
| `analyze_phase4.py`, cost figure | not yet (after the pairs are fixed) |

A new benchmark = one module in `xmad_bench/` + one entry in `config/base.yaml`
(`benchmarks:`). Agent and debate code stay untouched (C3.3, C2.2).

## Data

| Benchmark | Source (official) | Used split | Paragraphs / question | Gold |
|---|---|---|---|---|
| MuSiQue-Ans | github.com/StonyBrookNLP/musique, `musique_v1.0.zip` (CC BY 4.0) | `musique_ans_v1.0_dev.jsonl`, answerable only (2,417) | up to ~20, distribution printed by `tests/test_phase4_offline.py --real` | answer + aliases, `is_supporting` |
| 2WikiMultiHopQA | github.com/Alab-NII/2wikimultihop, `data_ids_april7.zip` (fixed sentence segmentation) | `dev.json` | 10 | one answer, `supporting_facts`, `type` |

Repeated paragraph titles (MuSiQue, 2Wiki) are made unique ("Title (2)") so that
Jaccard and evidence recall do not merge two different paragraphs.

## Step by step (cluster)

```bash
cd /path/to/workspace/xmad && git pull
cd 4_iteration
source /path/to/workspace/venvs/vllm-p3/bin/activate
export HF_HOME=/path/to/workspace/hf_cache
```

1. **Data** (login node, internet): `python download_benchmarks.py` -> check `data/*/SOURCE.json`
2. **Smoke tests** (GPU node) for the models of `runs.yaml` + judge: `python smoke_test.py --priority could --missing --gpus 0,1,2,3`
   (also done automatically at the start of `run_phase4.sbatch`)
3. **Offline tests** (no GPU): `python tests/test_phase4_offline.py --real`
   (`--real` also checks the downloaded files: counts, 20/10 paragraphs, gold paragraphs, 2Wiki types)
4. **Retriever check** (one GPU, minutes): `CUDA_VISIBLE_DEVICES=0 python retriever_check.py --n 50`
   -> `analysis/retriever_recall.csv`. Decide whether k = 3 passages per search is still enough for MuSiQue.
5. **Regression check** (one GPU): `python phase4.py run --only P4-HPQ-001 --n 30`
   then `python compare_regression.py` -> compares answer, EM, source and rounds per question
   with `3_iteration/results/P3-001_*` (same questions; at most single answers may differ by GPU noise).
6. **Smoke tests of all models + pre-test** in one batch job (whole node):
   `sbatch --export=ALL,MODE=pretest,PRIORITY=should run_phase4.sbatch`
   -> smoke tests of every model of the must/should runs (+ judge), then all 20 homogeneous
   pairs x 2 benchmarks with 30 questions (folders *_test), then `pretest_sanity.txt`
   (flags incl. evidence recall < 0.60 and a benchmark-specific round-1 EM threshold)
7. **Real runs**: `sbatch --export=ALL,PRIORITY=could run_phase4.sbatch` (all 132),
   then `sbatch --export=ALL,MODE=judge,PRIORITY=could run_phase4.sbatch`

## Defaults chosen (change in `config/base.yaml` / `runs.yaml` if needed)

- 1000 questions per benchmark, seed 42, the same sample for every pair of a benchmark
- MuSiQue: answerable questions only (MuSiQue-Ans)
- all Phase 3 conditions unchanged: judge deepseek-v4-flash, reasoning off, R_max 10,
  6/12 turns, max_tokens 8192, k = 3 passages per search
- single-agent baseline = round-1 answer of the homogeneous pairs (as Phase 3)

## Deviations from Phase 3 (disclose)

- **Qwen3.5-397B-A17B tool parser: `qwen3_xml` instead of `qwen3_coder`.** In both Phase 4
  smoke tests (2026-10-24) the vLLM server with `qwen3_coder` did not become ready (log ends
  during kernel warm-up / after the profiling run, no error), the second attempt with
  `qwen3_xml` passed (start-up 2380 s and 2195 s; Phase 3: 850 s). Both parsers read the same
  Qwen3 XML tool-call format (Phase 3 used `qwen3_xml` for Qwen3.8-27B and Qwen3.8-Flash-Next);
  the model output is the same, only malformed calls could be parsed differently. Check in the
  pre-test: invalid tool calls / missing answers of the 397B runs.
- **Server start-up limit** `ready_timeout_s` 3600 instead of 2400 (start-up time only).
- **Lost MCP connection (2026-10-31).** In 4 of 132 runs a connection to the MCP tool server
  dropped (`httpx.ReadError`; Phase 3 had it once, P3-017, 1 question). P4-MSQ-029/037 stopped at
  once (questions done before are valid); in P4-2WK-023/054 every later question failed in 0 s
  ("Client is not connected", 742 and 163 rows). `phase4.py drop-errors` removed these questions
  (backup `debate_results_with_errors.csv`, list in `drop_errors.json`) and `run --retry-failed`
  computed them again with the unchanged debate code. Since then `run_debate.py` stops a run on
  a lost connection instead of writing error rows.

## Notes for the evaluation

- Consensus stays exact match on the normalized answer (unchanged debate code).
  Aliases count for scoring, not for consensus: "Steve Jobs" vs "Steven Paul Jobs"
  goes to the judge, and the judge's answer is scored against all aliases.
- 2Wiki is scored against its single answer (as its official v1.0 script).
- F1 is the Phase 1-3 token F1 (no special yes/no rule), so all benchmarks and
  phases use the same metric.
